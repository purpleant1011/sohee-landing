## 제품 이해와 반영
1. 사장님이 매번 무엇을 시킬지 생각하지 않아도 된다. 빈 예약과 미응답 문의, 콘텐츠 공백을 찾아 먼저 제안하는 아침 브리핑을 추가했다.
2. 목표 하나가 기획·제작·승인·게시·대화·예약·보고·학습으로 이어진다. 일러스트, HTML 4단계 흐름, 실제적인 고객 대화/예약 상태 예시로 설명했다.
3. 매장 기억과 합의한 권한 안에서 일한다. 사장님은 중요한 결정에 참여하며, 문구를 고치거나 직접 편집할 수 있다는 설명을 넣었다.
4. 성과는 확인된 사실로 보고한다. 예약 확정과 예약금 확인 대기를 분리하고, 예시를 실제 성과로 소개하지 않는다.
5. 시작·성장·운영의 책임 범위를 비교하되 금액·임의 할당량·구매 버튼을 넣지 않았다.

문서는 제품 방향과 개발 청사진을 포함한다. 모든 기능이 현재 운영 중이라는 검증 자료로 취급하지 않는다. 실제 업무는 출시 단계와 연결 환경 및 권한에 따른다고 페이지에 명시했다.

## 실행 계획 및 완료 기준
1. 원문과 기존 페이지 조사
2. 목표가 끊기지 않는 메시지와 도식 구성
3. 이미지/업무 장면/책임 비교 구현
4. 모바일 수직 흐름 및 접근성 통합
5. Ego Lite 데스크톱·모바일 일괄 검토, 수정 및 확인
6. 검사와 빌드 후 커밋·푸시. 배포는 별도 지시 전까지 실행하지 않음.
